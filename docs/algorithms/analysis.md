# Анализ алгоритмов и доказательства

## Задача

Обоснуйте корректность алгоритма и оцените время по числу операций, отделив худший случай от амортизированной стоимости.

:::{container} task-facts

**Вход.** Размер n=4; цикл выполняет 1+2+3+4 действий.

**Результат.** 10 действий; общее число n(n+1)/2, то есть Θ(n²).

:::

**Предусловия.** Рассматриваем конечный вход размера $n\ge0$; стоимость выбранной базовой операции считается единичной.

### Проверка

Запустите пример: утверждения фиксируют ожидаемое поведение.

```python
n = 4
assert sum(range(1, n + 1)) == n * (n + 1) // 2 == 10
```

Алгоритм решает задачу для каждого допустимого входа. Его анализ отвечает на два разных вопроса: почему ответ верен и сколько ресурсов это решение использует. В этой главе `n` обозначает размер входа, а все асимптотические функции считаются неотрицательными при достаточно больших `n`.

## Модель стоимости

Сначала зададим, что считаем одной операцией. В обычной RAM-модели чтение или запись машинного слова, сравнение двух слов и арифметика над ними стоят `Θ(1)`. Если значения могут иметь произвольную длину, стоимость зависит и от числа битов: сложение `b`-битных чисел не обязано стоить константу. Поэтому оценка всегда относится к модели, а не к коду вообще.

Размер входа — не всегда одно число. Для графа естественны `|V|` и `|E|`; для двух строк — их длины `n` и `m`; для чисел — также длина двоичной записи. Например, алгоритм, полиномиальный по числовому значению `W`, может быть экспоненциальным по длине представления `log W`.

## Асимптотические обозначения

Пусть `f(n), g(n) ≥ 0` для всех достаточно больших `n`, причём `g(n) > 0`. Тогда:

- `f ∈ O(g)`, если существуют `c > 0` и `n₀`, такие что для всех `n ≥ n₀` выполнено `f(n) ≤ c g(n)`;
- `f ∈ Ω(g)`, если существуют `c > 0` и `n₀`, такие что для всех `n ≥ n₀` выполнено `f(n) ≥ c g(n)`;
- `f ∈ Θ(g)`, если одновременно `f ∈ O(g)` и `f ∈ Ω(g)`;
- `f ∈ o(g)`, если для каждого `c > 0` найдётся `n₀`, после которого `f(n) < c g(n)`; при существовании предела это эквивалентно `lim f(n)/g(n) = 0`;
- `f ∈ ω(g)`, если для каждого `c > 0` найдётся `n₀`, после которого `f(n) > c g(n)`; при существовании предела это эквивалентно `lim f(n)/g(n) = +∞`.

`O` — верхняя граница, `Ω` — нижняя, `Θ` — точный порядок с точностью до константы. Они не говорят сами по себе, худший это случай, ожидаемое время или амортизированная стоимость: этот смысл требуется указывать отдельно.

Если `ε > 0`, то `log^k n = o(n^ε)` для любого постоянного `k`; в частности, `n log n = o(n^{1+ε})`. Полином большей степени асимптотически доминирует полином меньшей степени, а любое `c^n` при `c > 1` доминирует любой полином. Основание логарифма несущественно для `Θ`, поскольку `log_a n = log_b n / log_b a`.

### Худшая, ожидаемая и амортизированная стоимость

Худшее время — максимум по входам размера `n`. Ожидаемое время берётся по явно заданному распределению случайных входов или случайных выборов алгоритма. Амортизированная оценка ограничивает стоимость последовательности операций детерминированно и не использует вероятностное предположение. Эти утверждения нельзя подменять друг другом.

Например, у QuickSort худшее время `Θ(n²)`, а ожидаемое время рандомизированного варианта `Θ(n log n)` по его случайному выбору опорных элементов. Для динамического массива удвоение ёмкости даёт `Θ(1)` амортизированную стоимость добавления, хотя отдельное расширение стоит `Θ(n)`.

## Как доказывать корректность

Спецификация алгоритма задаёт предусловие `P`, постусловие `Q` и эффект на состоянии программы. Обозначение Хоара `{P} C {Q}` означает: если команда `C` начинает работу в состоянии, удовлетворяющем `P`, и завершается, то результат удовлетворяет `Q`. Для полной корректности отдельно доказывают завершение.

Для цикла удобно найти инвариант `I` и вариант `V`:

1. **Инициализация:** перед первой итерацией верно `I`.
2. **Сохранение:** если перед итерацией верно `I` и условие цикла истинно, после тела снова верно `I`.
3. **Завершение:** неотрицательная целая величина `V` строго убывает на каждой итерации.
4. **Использование:** `I` вместе с отрицанием условия цикла влечёт постусловие `Q`.

Инвариант объясняет, почему цикл сохраняет нужную информацию; вариант исключает бесконечное выполнение. Одного инварианта для доказательства завершения недостаточно.

В Insertion Sort естественный инвариант внешнего цикла таков: перед итерацией с индексом `i` префикс `a[0:i]` отсортирован и состоит ровно из исходных элементов этого префикса. Внутренний цикл сдвигает вправо элементы, большие вставляемого, сохраняя их относительный порядок; затем вставка восстанавливает инвариант внешнего цикла. При `i = n` весь массив отсортирован, а перестановка элементов сохранена.

Для рекурсивного алгоритма обычно доказывают базовый случай и шаг по индукции по размеру задачи. Для жадного алгоритма часто подходит обменный аргумент: из оптимального решения строят решение, содержащее жадный выбор и не имеющее худшего качества. Для нижней оценки доказывают, что любой алгоритм в заданной модели обязан различить достаточно много случаев.

## Анализ циклов и рекуррентностей

Для последовательных частей складывают стоимости; для вложенных циклов суммируют число итераций, а не просто перемножают границы, если диапазон внутреннего цикла зависит от внешнего индекса. Например, сумма `1 + 2 + ⋯ + n = n(n+1)/2 = Θ(n²)`.

Рекурсивный алгоритм часто описывается уравнением

```text
T(n) = a T(n / b) + f(n), T(1) = Θ(1),
```

где `a ≥ 1` подзадач имеют размер примерно `n/b`, а `f(n)` покрывает разбиение и объединение. Для `n=b^h` дерево рекурсии имеет высоту `h = log_b n`; уровень `i` содержит `a^i` узлов стоимости `f(n/b^i)`.

**Пример.** Для Merge Sort

```text
T(n) = 2T(n/2) + Θ(n).
```

На каждом из `log₂ n` уровней суммарно сливается `Θ(n)` элементов, а листья в сумме стоят `Θ(n)`. Значит, `T(n)=Θ(n log n)`.

Для формулы `T(n)=aT(n/b)+f(n)` положим `p=log_b a`. Основная теорема даёт три случая при обычных предположениях о целочисленном делении и регулярности:

1. Если `f(n)=O(n^{p-ε})` для некоторого `ε>0`, то `T(n)=Θ(n^p)`.
2. Если `f(n)=Θ(n^p log^k n)` для `k≥0`, то `T(n)=Θ(n^p log^{k+1} n)`.
3. Если `f(n)=Ω(n^{p+ε})` и `a f(n/b) ≤ c f(n)` для некоторого `c<1`, то `T(n)=Θ(f(n))`.

Условия важны: теорема не применяется механически к любой рекуррентности. Например, для `T(n)=3T(n/2)+n` имеем `p=log₂3>1`, поэтому `n=O(n^{p-ε})` при некотором `ε>0`, и `T(n)=Θ(n^{log₂3})`.

Подстановка — это доказательство предполагаемой границы индукцией: подставляют оценку для меньших `n`, выбирают константы и проверяют неравенство. Дерево рекурсии удобно для поиска гипотезы. Основная теорема даёт быстрый вывод, когда выполнены её предпосылки.

## Амортизированный анализ

Для операций с фактическими стоимостями `c₁,…,cₘ` амортизированная оценка доказывает верхнюю границу суммы `Σ cᵢ` для любой допустимой последовательности операций. Она не обещает, что каждая отдельная операция дешева.

### Совокупный метод

Если для любой последовательности из `m` операций суммарная стоимость `O(m)`, то средняя стоимость на операцию в этой последовательности `O(1)`. Для стека с `PUSH`, `POP` и `MULTIPOP(k)` каждый элемент помещается один раз и удаляется не более одного раза. Поэтому `m` операций выполняют не более `O(m)` фактических действий, даже если один `MULTIPOP` удаляет много элементов.

### Потенциальный метод

Пусть `Φ(D) ≥ 0` — потенциал состояния структуры данных. Для перехода из `Dᵢ₋₁` в `Dᵢ` зададим амортизированную стоимость

```text
ĉᵢ = cᵢ + Φ(Dᵢ) − Φ(Dᵢ₋₁).
```

Сумма телескопируется:

```text
Σ ĉᵢ = Σ cᵢ + Φ(Dₘ) − Φ(D₀) ≥ Σ cᵢ − Φ(D₀).
```

Если `Φ(D₀)=0`, верхняя граница суммы амортизированных стоимостей является верхней границей фактической суммы.

Для стека возьмём `Φ(D)=|D|`. `PUSH` стоит `1` и увеличивает потенциал на `1`, поэтому `ĉ=2`. `POP` стоит `1` и уменьшает потенциал на `1`, поэтому `ĉ=0`. `MULTIPOP(k)`, удаляющий `r≤k` элементов, стоит `r` и меняет потенциал на `−r`, поэтому `ĉ=0`. Все операции имеют `O(1)` амортизированную стоимость.

### Метод бухгалтерского учёта

Назначают каждой операции амортизированный кредит `ĉᵢ` и считают разность `ĉᵢ−cᵢ` сохранённым балансом. Инвариант баланса: накопленные кредиты покрывают фактические расходы, то есть `Σĉᵢ ≥ Σcᵢ`. Для стека можно брать по два кредита за `PUSH`: один оплачивает вставку, второй остаётся на элемент и оплачивает его будущее удаление.

### Динамический массив

Рассмотрим добавление в массив ёмкости `C`, который при заполнении удваивает буфер и копирует `C` элементов. За `m` добавлений копирования происходят при ёмкостях `1,2,4,…`; сумма `1+2+4+⋯+2^j < 2^{j+1} ≤ 2m`. Вместе с `m` непосредственными записями общая стоимость `O(m)`, то есть `O(1)` амортизированно на добавление. Одна конкретная операция расширения всё ещё стоит `Θ(m)`.

## Нижняя оценка сравнительной сортировки

Детерминированную сравнительную сортировку можно представить бинарным деревом решений: внутренний узел сравнивает пару ключей, а лист задаёт итоговый порядок. Для различных ключей алгоритм должен различить все `n!` перестановок, поэтому дереву нужно не менее `n!` листьев. Дерево высоты `h` имеет не более `2^h` листьев, следовательно,

```text
h ≥ log₂(n!) = Ω(n log n).
```

Последнее следует, например, из `n! ≥ (n/e)^n`. Значит, в модели сравнений любая сортировка требует `Ω(n log n)` сравнений в худшем случае. Counting Sort и Radix Sort не противоречат результату: они используют дополнительные предположения о диапазоне/представлении ключей и не являются алгоритмами только сравнительной модели.

## Что следует помнить

- Сначала задайте модель стоимости и параметры входа.
- Отделяйте верхнюю, нижнюю и точную асимптотические границы.
- Различайте худшее, ожидаемое и амортизированное время.
- Доказывайте и сохранение корректности, и завершение.
- Для рекуррентности проверьте условия метода, прежде чем применять формулу.
- Амортизированная `O(1)` допускает редкую операцию за `Θ(n)`; она контролирует сумму последовательности.
