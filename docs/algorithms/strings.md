# Поиск образца в строке

## Задача

Найдите все позиции начала образца в тексте, включая перекрывающиеся вхождения.

:::{container} task-facts

**Вход.** Текст ababa, образец aba.

**Результат.** Позиции [0, 2].

:::

**Предусловия.** Индексы строк относятся к кодовым точкам; пустой образец встречается в $n+1$ позиции.

### Проверка

Запустите пример: утверждения фиксируют ожидаемое поведение.

```python
from algorithms.strings import knuth_morris_pratt

assert knuth_morris_pratt.search("ababa", "aba") == [0, 2]
```

Даны текст `T` длины `n` и образец `P` длины `m`. Требуется вернуть все позиции `i`, для которых `T[i..i+m) = P`, в возрастающем порядке. Вхождения могут перекрываться. Для пустого образца принимаем соглашение: совпадение начинается на каждой границе текста, то есть ответ равен `0, 1, ..., n`; если `m > n`, ответ пуст.

Код Python ниже индексирует `str` по кодовым точкам Unicode. Ни одна реализация не нормализует Unicode: например, визуально одинаковые составные и разложенные последовательности считаются разными, если их элементы различаются.

## Наивный поиск

На каждой допустимой позиции сравниваем образец с соответствующим окном текста слева направо.

```{literalinclude} ../../src/algorithms/strings/naive.py
:language: python
:caption: src/algorithms/strings/naive.py
```

При фиксированной позиции сравнение сообщает либо первое несовпадение, либо полное совпадение. Перебор всех `n − m + 1` окон потому находит ровно все позиции. Перекрытия не теряются, поскольку после совпадения следующая проверка сдвигается только на один символ.

В худшем случае, например для `T = aⁿ` и `P = aᵐ⁻¹b`, сравнивается `m` символов почти в каждом окне: время `Θ((n − m + 1)m)`, дополнительная память `O(1)` без учёта списка ответа. Лучший случай при немедленном несовпадении каждого окна — `Θ(n − m + 1)`.

## Префиксная функция

Для непустой строки `S` определим `π[i]` как длину наибольшего собственного префикса `S[0..i]`, являющегося также суффиксом этого фрагмента. Собственный префикс короче самого фрагмента. Для пустой строки возвращается пустой список.

```{literalinclude} ../../src/algorithms/strings/prefix_function.py
:language: python
:caption: src/algorithms/strings/prefix_function.py
```

Перед обработкой `S[i]` переменная `border` равна длине наибольшей границы уже обработанного префикса `S[0..i)`. Если следующий символ не продолжает эту границу, любая более длинная граница-кандидат обязана быть границей текущей границы. Поэтому переход `border = π[border − 1]` перебирает кандидатов в порядке убывания и не пропускает возможный ответ. Когда символы совпали, граница удлиняется на один; если кандидатов не осталось, правильная длина равна нулю. Индукция по `i` доказывает корректность всех значений.

Внешний цикл делает `m − 1` шагов. Каждое увеличение `border` повышает его не более чем на единицу за шаг, а суммарное число уменьшений не превосходит числа предыдущих увеличений. Следовательно, время `O(m)`, память `O(m)`.

## KMP

Knuth–Morris–Pratt использует `π` образца. После несовпадения уже совпавший суффикс текста сохраняет только ту часть, которая одновременно является префиксом образца; символы текста повторно не просматриваются. После полного совпадения алгоритм откатывается к наибольшей собственной границе, поэтому находит и перекрывающиеся вхождения.

```{literalinclude} ../../src/algorithms/strings/knuth_morris_pratt.py
:language: python
:caption: src/algorithms/strings/knuth_morris_pratt.py
```

Инвариант перед чтением очередного `T[i]`: `matched` — длина наибольшего префикса `P`, равного суффиксу уже прочитанного текста, который может продолжить совпадение на позиции `i − matched`. При несовпадении прежние `matched` символов текста уже известны. Возможное совпадение с тем же концом текста должно оканчиваться на границе совпавшей части `P`; префиксная функция перебирает границы от наибольшей к меньшей. Значит, откаты не теряют кандидатов. При равенстве расширяется совпавший префикс, а при `matched = m` фиксируется точное вхождение и состояние откатывается к собственной границе, сохраняя инвариант и перекрытия. Это доказывает полноту и отсутствие ложных позиций.

Для времени используем потенциал `matched`: каждый шаг текста увеличивает его не более чем на единицу; каждый откат строго уменьшает, поэтому суммарно откатов не больше суммарных увеличений `O(n)`. Построение `π` занимает `O(m)`. Итого время `O(n + m)`, память `O(m)` плюс `O(k)` для `k` результатов.

## Z-функция и поиск

Значение `z[i]` — длина наибольшего общего префикса строки и её суффикса, начинающегося в `i`; по соглашению `z[0] = |S|`. Для пустой строки массив пуст.

```{literalinclude} ../../src/algorithms/strings/z_function.py
:language: python
:caption: src/algorithms/strings/z_function.py
```

Алгоритм хранит самый правый уже доказанный интервал `[l, r)`, совпадающий с префиксом. Если `i < r`, то начало совпадения известно как минимум до `r`; значение из `z[i − l]` переносится, но ограничивается `r − i`. Дальнейшие сравнения продолжают с уже проверенной границы. Если новый интервал выходит правее `r`, он становится текущим. Каждый успешный внешний шаг расширяет `r` не более чем до `|S|`, а неуспешное сравнение добавляет лишь постоянную работу на позицию. Поэтому время `O(|S|)`, память `O(|S|)`.

Для поиска соединяем `P`, уникальный разделитель и `T`. Python использует объект `None`, отсутствующий среди элементов `str`. Позиция `i` является вхождением тогда и только тогда, когда Z-значение в соответствующей позиции текста не меньше `m`.

```{literalinclude} ../../src/algorithms/strings/z_search.py
:language: python
:caption: src/algorithms/strings/z_search.py
```

Конкатенация имеет длину `n + m + 1`; вычисление Z-массива и извлечение позиций занимают `O(n + m)` времени и памяти, не считая `O(k)` на ответ.

## Rabin–Karp

Полиномиальный хеш последовательности цифр `x₀, ..., xₘ₋₁` равен `Σ xᵢ bᵐ⁻¹⁻ⁱ mod q`. При сдвиге окна старшая цифра удаляется умножением на `bᵐ⁻¹`, остальные сдвигаются на разряд, затем добавляется новый символ. Код использует `q = 1 000 000 007`, фиксированное `b = 911 382 323` и цифру `символ + 1`.

```{literalinclude} ../../src/algorithms/strings/rabin_karp.py
:language: python
:caption: src/algorithms/strings/rabin_karp.py
```

Хеш равных строк одинаков, но обратное неверно: разные строки могут столкнуться по модулю `q`. Поэтому при равенстве хешей код обязательно проверяет символы. Ответ всегда точен; коллизия может лишь добавить сравнение. Так как проверок кандидатов до `n − m + 1`, а сравнение каждого кандидата стоит `O(m)`, худшее время равно `O(nm)`. Хеши и окно требуют `O(1)` дополнительной памяти, без списка ответа.

Вероятностная оценка относится к другой, рандомизированной схеме, а не к коду выше. Если для каждой пары сравниваемых строк основание независимо и равномерно выбирается из `𝔽q \ {0}`, а строки фиксированы до выбора основания, разность хешей — ненулевой многочлен степени не выше `m − 1`. У него не более `m − 1` корней, поэтому вероятность столкновения одной фиксированной пары не больше `(m − 1)/(q − 1)`. Для `d` независимых оснований вероятность одновременной коллизии не больше `((m − 1)/(q − 1))ᵈ`. Эта граница не применима к фиксированному основанию, адаптивно выбранным после наблюдения основаниям или перемножению вероятностей без независимости. Проверка кандидата всё равно нужна, чтобы результат оставался точным.

## Trie

Trie хранит множество слов как дерево общих префиксов. Путь от корня задаёт строку, а отдельный флаг `terminal` отмечает, что именно эта строка добавлена как слово: внутренний узел может быть префиксом, но не словом. Корень соответствует пустому префиксу всегда, однако пустое слово хранится только после `insert("")`.

```{literalinclude} ../../src/data_structures/trie.py
:language: python
:caption: src/data_structures/trie.py
```

После чтения первых `j` символов поиска состояние находится в единственном узле, чей путь равен `word[0..j)`. Если ребра нет, такого слова или префикса нет; если все рёбра пройдены, `starts_with` возвращает истину. Для `search` дополнительно требуется `terminal`: это исключает ложное принятие собственного префикса слова. Индукция по `j` доказывает инвариант пути, а значит, оба результата точны. Для строки длины `m` время составляет `O(m)` в среднем при хеш-таблице переходов; память — `O(Σ|w|)` узлов и рёбер, где сумма берётся по вставленным словам и общие префиксы учитываются один раз.

## Суффиксный массив и LCP

Суффиксный массив `SA` — перестановка начальных позиций текста, отсортированная по соответствующим суффиксам. `LCP[i]` хранит длину общего префикса соседних суффиксов `SA[i−1]` и `SA[i]`; `LCP[0]=0`. Пара `SA, LCP` поддерживает поиск и анализ повторяющихся подстрок без явного хранения всех суффиксов.

```{literalinclude} ../../src/algorithms/strings/suffix_array.py
:language: python
:caption: src/algorithms/strings/suffix_array.py
```

Перед шагом ширины `w` ранг позиции задаёт лексикографический порядок первых `w` символов суффикса, включая признак того, что суффикс закончился. Поэтому сортировка пар `(rank[i], rank[i+w])`, где отсутствующая вторая половина имеет ранг меньше любого существующего, упорядочивает первые `2w` символов. Перенумерация равных пар сохраняет это утверждение с шириной `2w`; после `⌈log₂ n⌉` шагов сравниваются целые суффиксы. Уникальные ранги позволяют остановиться раньше. Финальный `rank[start]` уже задаёт позицию суффикса в отсортированном массиве; Kasai использует его без отдельной обратной перестановки. Строки длины ноль и один обрабатываем сразу. На каждом из `O(log n)` шагов сравнительная сортировка занимает `O(n log n)`, итого `O(n log² n)` времени и `O(n)` вспомогательной памяти.

Kasai строит LCP по позициям текста, используя обратный массив рангов. Если суффикс позиции `i` имеет общий префикс длины `h` с предыдущим в лексикографическом порядке, то для `i+1` длина общего префикса с его соседом не меньше `h−1`: удаление первого символа оставляет общий хвост, а лексикографическое место хвостов не может иметь между ними суффикс, который нарушил бы эту нижнюю границу. Алгоритм начинает сравнение с `max(h−1,0)`. Переменная `h` при успешных сравнениях увеличивается, но суммарно не более `n` раз; на каждой позиции после записи она уменьшается не более чем на единицу. Следовательно, все сравнения Kasai занимают `O(n)` времени, а массивы рангов и результата — `O(n)` памяти.

Python str индексируется Unicode-кодовыми точками. Суффиксы сравниваются по кодовым точкам, и LCP измеряется в них. Нормализация Unicode не выполняется: визуально одинаковые строки с разным представлением могут давать разные индексы.
