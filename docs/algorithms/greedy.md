# Жадные алгоритмы

## Задача

Выберите совместимые интервалы максимальной мощности и объясните безопасность локального выбора.

:::{container} task-facts

**Вход.** Интервалы [(0, 2), (1, 3), (2, 4)].

**Результат.** Выбраны исходные индексы [0, 2].

:::

**Предусловия.** Для каждого интервала $s_i<f_i$; касание концов разрешено. У дробного рюкзака и Хаффмана отдельные условия.

### Проверка

Запустите пример: утверждения фиксируют ожидаемое поведение.

```python
from algorithms.greedy import interval_scheduling

assert interval_scheduling.select([(0, 2), (1, 3), (2, 4)]) == [0, 2]
```

Жадный алгоритм на каждом шаге фиксирует локально привлекательный выбор. Само по себе это описание не даёт гарантии оптимальности: её нужно доказывать для конкретной задачи. Здесь используются три разных результата: обменный аргумент для непересекающихся интервалов, линейная оптимизация для дробного рюкзака и структурная теорема для кодов Хаффмана.

## Максимальное число непересекающихся интервалов

На входе конечный набор полуоткрытых интервалов `[s_i,f_i)` с `s_i ≤ f_i`. Требуется выбрать подмножество максимальной мощности, где интервалы не пересекаются. Полуоткрытая модель означает, что интервал, заканчивающийся в момент `t`, совместим с интервалом, начинающимся в `t`. Алгоритм возвращает индексы выбранных интервалов во входном массиве в порядке выбора.

```{literalinclude} ../../src/algorithms/greedy/interval_scheduling.py
:language: python
```

**Доказательство обменом.** Пусть `g` — интервал с наименьшим временем окончания, выбранный первым жадным шагом, а `o` — первый интервал некоторого оптимального решения. По определению `f_g ≤ f_o`. Заменим `o` на `g`. Все следующие интервалы оптимального решения начинались не раньше `f_o`, а значит, начинаются не раньше `f_g`; после замены расписание остаётся допустимым и сохраняет число интервалов. Следовательно, существует оптимальное решение, начинающееся с `g`. После фиксации `g` остаётся та же задача на интервалах, начинающихся не раньше `f_g`. Индукция по числу оставшихся интервалов доказывает оптимальность всех последующих выборов.

Сортировка занимает `O(n log n)` времени; один проход — `O(n)`. Копия упорядоченных индексов и результат занимают `O(n)` памяти. При одинаковом окончании можно выбирать любой интервал; реализация детерминированно сохраняет исходный порядок. Интервалы длины ноль допустимы.

## Дробный рюкзак и граница жадности

Предмет `i` имеет положительный вес `w_i` и неотрицательную ценность `v_i`. Вместимость равна `W`. В дробном варианте можно взять долю `x_i ∈ [0,1]`, поэтому задача имеет вид

```text
максимизировать Σ v_i x_i
при условиях   Σ w_i x_i ≤ W,  0 ≤ x_i ≤ 1.
```

Плотность предмета — `ρ_i = v_i / w_i`. Рассматриваем предметы по невозрастанию плотности, берём каждый целиком, пока он помещается, и при необходимости берём долю следующего.

```{literalinclude} ../../src/algorithms/greedy/fractional_knapsack.py
:language: python
```

**Почему выбор оптимален.** Рассмотрим любое допустимое решение, в котором предмет плотности `ρ_i` взят не полностью, а предмет меньшей плотности `ρ_j < ρ_i` взят в положительной доле. Перенос веса `ε > 0` от `j` к `i` сохраняет общий вес и увеличивает ценность на `ε(ρ_i-ρ_j)>0`. Поэтому в оптимуме нельзя оставлять свободную долю более плотного предмета, пока взята менее плотная доля. Именно такую структуру строит алгоритм. Сортировка требует `O(n log n)` времени, проход — `O(n)`; память для копии — `O(n)`.

Этот обмен невозможен, если предметы неделимы. Например, при `W=50` и предметах `(w,v)=(10,60),(20,100),(30,120)` плотности равны `6,5,4`. Жадный выбор по плотности берёт первые два предмета, получает `160` и не может добавить третий. Оптимально взять предметы весом `20` и `30`, получив `220`. Для 0/1-рюкзака нужна другая структура решения, например динамическое программирование.

## Код Хаффмана

Пусть символы `c` имеют положительные частоты `f(c)`. Требуется назначить двоичные кодовые слова так, чтобы ни одно слово не было префиксом другого, минимизируя среднюю длину, или эквивалентно взвешенную длину

```text
L = Σ_c f(c) · |code(c)|.
```

Дерево префиксного кода имеет символы в листьях, а длина кода — глубина листа. Алгоритм Хаффмана многократно объединяет два узла с наименьшими весами: их новый родитель получает сумму весов. Рёбра к левому и правому потомкам кодируются битами `0` и `1`.

```{literalinclude} ../../src/algorithms/greedy/huffman.py
:language: python
```

**Оптимальность.** В полном двоичном дереве есть пара листьев-братьев максимальной глубины. Среди символов с двумя наименьшими частотами `a,b` можно выбрать оптимальное дерево, где они стоят в этой паре. Действительно, если более частый символ стоит глубже, обмен его с `a` не увеличивает сумму `Σ f(c)d(c)`; тот же обмен применяется к `b`. Обозначим через `T'` дерево, в котором листья `a,b` заменены одним псевдосимволом частоты `f(a)+f(b)`. Для соответствующего дерева `T` исходная стоимость равна

```text
L(T) = L(T') + f(a) + f(b),
```

поскольку глубина каждого из двух листьев на единицу больше глубины псевдосимвола. По индукции оптимальное поддерево `T'` строится тем же алгоритмом, а раскрытие псевдосимвола в двух потомков даёт оптимальное дерево для исходного алфавита. Это доказывает корректность каждого объединения и конечного кода.

Куча выполняет `k-1` извлечений и вставок за `O(k log k)` времени при `k` символах; дерево и коды требуют `O(k)` узлов плюс `O(Σ|code(c)|)` символов результата. Пустой алфавит даёт пустое отображение; единственный символ кодируется строкой `0`, чтобы символ можно было передавать непустым кодовым словом. Равные частоты могут дать разные коды с той же оптимальной стоимостью.
