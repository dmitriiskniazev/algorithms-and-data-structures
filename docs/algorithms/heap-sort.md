# Сортировка кучей

## Задача

Отсортируйте последовательность на месте, последовательно помещая максимум рабочей кучи в конец.

:::{container} task-facts

**Вход.** [3, 1, 2, 1].

**Результат.** [1, 1, 2, 3]; вспомогательная память O(1).

:::

**Предусловия.** `<` задаёт строгий слабый порядок; исходное хранилище допускает перестановку значений.

## Контракт, идея и корректность

Значения сравниваются напрямую через `<`, задающий строгий слабый порядок. Сортируется исходное хранилище; устойчивость не гарантируется.

Построим max-heap по выбранному порядку. Корень — последний по этому порядку элемент. Поменяем его с последним элементом рабочей кучи, уменьшим её длину, восстановим свойство кучи просеиванием вниз. Инвариант: рабочий префикс является кучей, исключённый суффикс отсортирован и лежит на окончательных местах. Каждый шаг увеличивает суффикс на один элемент.

Операции кучи находятся в [отдельном уроке](../data-structures/heap.md) и используются также priority queue. Сортировка не создаёт отдельный контейнер кучи: операции работают в переданном диапазоне.

## Варианты и сложность

| Построение | Время построения | Идея |
|---|---|---|
| Последовательные `sift_up` | O(n log n) в худшем случае | Добавлять элементы по одному; применяется в priority queue |
| Bottom-up `heap.build` | O(n) | Просеивать внутренние узлы от нижнего уровня к корню; используется в HeapSort |

Построение линейно: узлов высоты h не больше порядка n/2^(h+1), и сумма затрат n·Σ h/2^h ограничена O(n). Извлечения стоят O(n log n), дополнительная память O(1). Итеративное просеивание не расходует рекурсивный стек. Гарантия O(n log n) сохраняется для каждого входа, но это не означает, что HeapSort быстрее QuickSort на практике.
