## Точные задачи решения

Задача решения задаёт множество двоичных строк, ответ для каждой строки — `yes` или `no`. Например, экземпляр Clique состоит из графа `G=(V,E)` и числа `k`; ответ `yes`, если в графе есть `k` попарно смежных вершин. В Vertex Cover спрашивается о множестве не более чем из `k` вершин, инцидентном каждому ребру. В Subset Sum заданы целые веса и цель `T`, требуется подмножество с суммой ровно `T`. В задаче решения TSP заданы взвешенный граф и порог `B`; спрашивается, есть ли гамильтонов цикл стоимости не более `B`.

Точность постановки существенна: оптимизационная задача «найти кратчайший тур» и задача решения «существует ли тур длины ≤ B?» связаны, но являются разными задачами. Сертификат задаёт проверяемый свидетель ответа `yes`; отрицательный ответ сертификатом здесь не сопровождается.

## P, NP и полиномиальные сертификаты

Рассматриваем язык `L ⊆ {0,1}*` и обозначаем длину кодировки входа через `N`. Класс `P` состоит из языков, для которых детерминированный алгоритм решает принадлежность за время `N^c` при некоторой постоянной `c`. Здесь `N` — число битов, а не числовое значение закодированного числа. Цикл длины `T` может быть экспоненциальным по длине двоичного представления `T`.

Класс `NP` состоит из языков, для которых существует полиномиально ограниченная длина сертификата `y` и детерминированный проверяющий алгоритм `V`, такой что

```text
x ∈ L ⇔ существует y, |y| ≤ p(|x|), для которого V(x, y) = accept,
```

а время проверки ограничено полиномом от `|x|+|y|`. Эквивалентно, NP — класс задач, решаемых недетерминированной машиной за полиномиальное время. Утверждение `P ⊆ NP` следует, например, из пустого сертификата для задачи из P. Известно ли `P = NP`, не решено; курс не использует ни равенство, ни неравенство как доказанный факт.

Индексы вершин или элементов образуют сертификаты длины `O(n log n)` бит. Проверка Clique перечисляет пары выбранных вершин и ищет рёбра: `O(k²)` проверок принадлежности после подготовки множества рёбер. Проверка Vertex Cover проходит по всем рёбрам и сертификату. В приведённых реализациях используются хеш-множества в Python; ожидаемая стоимость Python-проверки линейна по числу рёбер и размеру сертификата. Даже при худшей деградации хеш-таблицы Python перебор элементов множества даёт полиномиальную верхнюю границу. Проверка Subset Sum складывает не более `n` выбранных целых чисел и сравнивает результат с целью; в битовой модели стоимость полиномиальна по суммарной длине двоичных записей, причём Python считает точно. Проверка TSP проверяет размеры матрицы, все `n` вершин и `n` рёбер цикла; сложение и сравнение также имеют полиномиальную битовую стоимость. Отсутствующее ребро задаётся `None`.

Таким образом, явный свидетель можно проверить за полиномиальное время. Это доказывает принадлежность задачи NP, но не доказывает, что поиск решения труден: для NP-полноты нужен отдельный шаг.

## Many-one редукции и NP-полнота

Полиномиальная many-one редукция `A ≤p B` — это вычислимое за полиномиальное время преобразование `f`, для которого для каждого входа `x`

```text
x ∈ A ⇔ f(x) ∈ B.
```

Если `A ≤p B`, то алгоритм для `B` даёт алгоритм для `A`: вычислить `f(x)` и передать результат решателю `B`. Направление важно: редукция от уже известной трудной задачи `A` к целевой `B` переносит трудность на `B`. Если `A` NP-полна и `A ≤p B`, то `B` NP-трудна. Задача NP-трудна, если каждая задача из NP полиномиально many-one сводится к ней; она NP-полна, если одновременно NP-трудна и принадлежит NP. Если принадлежность NP не доказана, слово «полная» не следует из NP-трудности.

### Редукция 3-SAT к Clique

Пусть дана 3-CNF формула с клаузами `C₁,…,Cₘ`, в каждой ровно три литерала. Строим граф так:

1. Для каждого вхождения литерала в клаузу создаём отдельную вершину `(i, ℓ)`. Всего `3m` вершин.
2. Соединяем `(i, ℓ)` и `(j, r)`, только если `i ≠ j` и литералы не противоречат друг другу, то есть не являются парой `x` и `¬x`.
3. Устанавливаем `k=m`.

Построение полиномиально: просматриваем не более `9·binom(m,2)` пар вершин из разных клауз; проверка того, противоречат ли два литерала, полиномиальна по длине их имён. Поэтому и размер результата, и время построения полиномиальны по длине исходной формулы.

Докажем обе стороны эквивалентности.

**Если формула выполнима, то граф содержит clique размера `m`.** Возьмём удовлетворяющее присваивание. В каждой клаузе оно делает истинным хотя бы один литерал; выберем по одному такому вхождению. Выбранные вершины относятся к разным клаузам. Между ними есть ребро: две выбранные истинные литеральные формулы не могут быть противоположными `x` и `¬x`. Значит, все `m` выбранных вершин попарно смежны.

**Если граф содержит clique размера `m`, то формула выполнима.** Вершины одной клаузы не соединены, следовательно, clique содержит не более одной вершины из каждой клаузы. Так как клауз `m` и вершин в clique тоже `m`, она содержит ровно одну вершину каждой клаузы. Между любыми двумя выбранными литералами есть ребро, поэтому среди них нет противоположной пары `x, ¬x`. Можно присвоить переменным значения, делающие все выбранные литералы истинными; противоречия нет. Тогда в каждой клаузе есть истинный литерал, и формула выполнима.

Мы доказали `φ ∈ 3-SAT ⇔ (Gφ,m) ∈ Clique`. Так как 3-SAT NP-полна, Clique NP-трудна; вместе с проверкой сертификата Clique это даёт NP-полноту Clique.

## Точный перебор, эвристики и аппроксимации

Точный перебор гарантирует ответ, но обычно имеет экспоненциальное время: SAT можно решить проверкой `2^v` присваиваний для `v` переменных; Clique и Vertex Cover — перебором `2^n` подмножеств вершин; Subset Sum — `2^n` подмножеств элементов; неориентированный TSP — `(n−1)!/2` циклов при фиксированной стартовой вершине. Перебор полезен для малых входов и эталонных тестов, но не становится полиномиальным оттого, что запись кода коротка.

Алгоритм может быть точным и быстрее полного перебора на отдельных классах входов, не имея полиномиальной худшей оценки для общего случая. Например, динамика Subset Sum за `O(nT)` времени использует числовую цель `T`; при двоичном кодировании `T` это псевдополиномиальная оценка, поскольку `T` экспоненциально от `log T`.

Эвристика выбирает правдоподобное решение, но без анализа не обещает ни оптимальность, ни ограниченное отношение к оптимуму. Жадный выбор вершин с большой степенью для Clique может выдать допустимую клику, однако сам по себе не даёт нижней границы на размер максимальной клики. Поэтому слово «приближённый» нельзя использовать как синоним «быстрый» или «разумный на примерах».

У аппроксимации есть математическая гарантия. Для минимального Vertex Cover можно построить **максимальное по включению паросочетание**: просматривая рёбра, добавлять ребро, если ни один его конец ещё не выбран. Затем вернуть оба конца каждого ребра паросочетания. Построенное паросочетание действительно максимально: любое пропущенное ребро уже касается выбранной вершины. Поэтому возвращённое множество покрывает каждое ребро и имеет размер ровно `2|M|`, так как рёбра паросочетания не имеют общих концов. Любое vertex cover обязано выбрать хотя бы один конец каждого из `|M|` непересекающихся рёбер, откуда `OPT ≥ |M|`. Следовательно,

```text
|C| = 2|M| ≤ 2 OPT.
```

Это 2-аппроксимация: она всегда возвращает допустимое решение не более чем вдвое больше оптимального. Утверждение относится к минимизационной задаче Vertex Cover и не обещает такого отношения для Clique, TSP или Subset Sum.

## Что следует помнить

- `P` говорит о полиномиальном времени решения, `NP` — о полиномиальной проверке сертификата.
- Полиномиальность относится к длине двоичной записи; время `O(T)` не полиномиально по длине числа `T`.
- Для NP-полноты нужны оба доказательства: задача в NP и задача NP-трудна.
- В `A ≤p B` трудность переносится от `A` к `B`; эквивалентность yes/no должна работать в обе стороны.
- Точный перебор, эвристика и аппроксимация имеют разные виды гарантий.
