# Конструирование стеков и очередей

## Задача

Реализуйте один интерфейс разными способами хранения и объясните стоимость каждой операции.

:::{container} task-facts

**Вход.** Добавления 1 и 2 в пустой стек.

**Результат.** Извлечения 2 и 1; для очереди на тех же данных порядок обратный: 1 и 2.

:::

**Предусловия.** Пустое извлечение вызывает IndexError; конкретные ограничения задаются в каждой задаче.

## Общий контракт

$S=(s_0,\ldots,s_{n-1})$ — стек от дна к вершине; $Q=(q_0,\ldots,q_{n-1})$ — очередь от головы к хвосту. Через $A\mathbin{\|}B$ обозначена конкатенация, через $\operatorname{rev}(A)$ — обращение последовательности.

- Изменяемые контейнеры: `push(x)` добавляет значение, `pop()` удаляет и возвращает его, `peek()` только читает.
- Стек возвращает $s_{n-1}$, очередь — $q_0$. Для `peek` / `pop` требуется $n>0$; пустой доступ вызывает `IndexError` согласно общему интерфейсу курса.
- Размер: Python `len(container)` и `bool(container)`.
- В персистентных контейнерах `push` и `pop` возвращают **новый контейнер**. Извлекаемое значение читается через `peek` до `pop`; исходная версия сохраняется.
- Оценки используют RAM-модель с $O(1)$ на копирование/перемещение одного значения и сравнение. Для дорогого `T` его стоимость учитывается отдельно; освобождение версий и работа сборщика памяти также выделяются отдельно.

``````{dropdown} Решение

```{literalinclude} ../../src/data_structures/queue/two_stacks.py
:language: python
```

**Идея.** Входной стек принимает новые элементы. Выходной отдаёт старые; когда он пуст, полностью переверните в него входной.

**Сложность и ограничения.** `push` — амортизированное $O(1)$; `peek` и `pop` могут вызвать перенос за $O(n)$, но также имеют амортизированную оценку $O(1)$. Память — $O(N)$. Амортизация динамических массивов добавляет лишь постоянный множитель к суммарной работе.
``````

``````{dropdown} Решение

```{literalinclude} ../../src/data_structures/stack/extrema/minimum.py
:language: python
```

**Идея.** Для каждой глубины сохраните минимум соответствующего префикса. `stack.extrema.minimum.Stack` хранит только минимум, запрос называется `extreme()`. Для максимума выбирается симметричный модуль `maximum`.

**Корректность.** Инвариант: кеш глубины $i$ равен $m_i=\min(s_0,\ldots,s_i)$. База — $m_0=s_0$; добавление вычисляет $m_i=\min(m_{i-1},s_i)$. Удаление снимает запись глубины $i$ и открывает готовый минимум глубины $i-1$. Повторяющиеся значения не требуют особого случая.

**Сложность и ограничения.** `extreme` и `peek` — $O(1)$, `push` — амортизированное $O(1)$, `pop` — амортизированное $O(1)$. Активных записей — $O(n)$; буфер может удерживать историческую ёмкость. Сравнение значений считается $O(1)$.
``````

## 8. Персистентный стек

Пусть $S_v$ — содержимое версии $v$. Реализуйте $push(v,x)=v'$ с $S_{v'}=S_v\mathbin{\|}(x)$ и $pop(v)=v'$ с $S_{v'}=S_v[:-1]$ при $|S_v|>0$. Версия $v$ сохраняется. Требуются $O(1)$ на операцию и сохранение версии, $O(1)$ новой памяти на `push`.

``````{dropdown} Решение

```{literalinclude} ../../src/data_structures/stack/persistent.py
:language: python
```

**Идея.** Версия хранит ссылку на неизменяемую голову и размер. `push` создаёт один узел со ссылкой на прежнюю голову; `pop` возвращает версию с прежним хвостом. Эти узлы разделяются всеми версиями.

**Корректность.** Инвариант: цепочка узлов от головы содержит $s_{n-1},\ldots,s_0$ и имеет длину $n$. Новый узел добавляет $x$ перед цепочкой, а переход к хвосту удаляет её первый элемент. Старые узлы не изменяются, значит любой старый дескриптор продолжает задавать прежнюю последовательность.

**Сложность и ограничения.** `push`, `pop`, `peek`, размер и сохранение дескриптора — $O(1)$; `push` выделяет один узел, `pop` — только дескриптор. Для $p$ успешных добавлений и $v$ сохранённых дескрипторов память — $O(p+v)$ до освобождения недостижимых узлов.

Python использует неизменяемые `frozen`-объекты. Освобождение последней ссылки на цепочку из $k$ узлов требует $O(k)$ работы.
``````

## 9. Персистентная очередь

Реализуйте $push(v,x)=v'$ с $Q_{v'}=Q_v\mathbin{\|}(x)$ и $pop(v)=v'$ с $Q_{v'}=Q_v[1:]$ при $|Q_v|>0$. Используйте два персистентных стека. Получите $O(1)$ для `peek`, `push` и сохранения версии; для `pop` допустимо $O(n)$ в худшем случае. Исследуйте стоимость ветвления.

``````{dropdown} Решение

```{literalinclude} ../../src/data_structures/queue/persistent.py
:language: python
```

**Идея.** Передний стек хранит начало очереди вершиной вперёд, задний — остаток в обратном порядке. Непустая версия всегда имеет непустой передний стек. `pop` снимает его вершину; если он опустел, задний стек полностью переворачивается в новый передний.

**Корректность.** Инварианты: $Q=\operatorname{top}(front)\mathbin{\|}\operatorname{rev}(\operatorname{top}(rear))$ и $|Q|>0\implies |front|>0$. `push` добавляет $x$ в конец этой последовательности; добавление в пустую очередь сразу формирует передний стек. `pop` удаляет первый элемент и при необходимости восстанавливает второй инвариант переносом. Оба исходных стека сохраняются, поэтому прежняя версия не меняется.

**Сложность и ограничения.** `push`, `peek`, размер и сохранение версии — $O(1)$. `pop` — $O(1)$ без переноса и $O(n)$ с переносом, выделяющим $O(n)$ новых узлов. В одной последовательной истории из пустой очереди каждое вхождение элемента переносится из заднего стека в передний не более одного раза: $m$ операций требуют $O(m)$ работы.

 В Python переносятся ссылки на те же объекты. У обеих структур персистентность относится к расположению элементов; изменение самого пользовательского объекта не откатывается.

Тесты: {download}`Python <../../tests/data_structures/queue/test_persistent_queue.py>`.
``````

### Ветвление и повторный перенос

Из пустой версии выполните `push(0), push(1), …, push(n)`. Получится очередь с одним элементом в переднем стеке и $n$ элементами в заднем. Сохраните её как $v$ и независимо вычислите $b$ версий `v.pop()`.

Каждый вызов заново переносит $n$ элементов. После построения $v$ выполнено $b$ операций, но их общая работа равна $\Theta(bn)$. Если сохранить все результаты, они также выделят $\Theta(bn)$ узлов. Значит доказательство через «элемент переносится один раз» применимо к одному пути из пустой версии и не переносится на всё дерево версий. Продолжение уже большой старой версии тоже может начать с дорогого переноса: в его оценку входит построение этой версии.

Это ограничение простой реализации на двух строгих стеках; реальное время для произвольного ветвления в её контракт не входит.

## 10. Откат, снимок и независимые продолжения

Для $v_0=\varnothing$ постройте историю $H=(v_0,\ldots,v_k)$. Реализуйте следующие действия над `persistent.Stack` и `persistent.Queue`, сохраняя доступ к выбранным версиям:

1. После операции запишите новый дескриптор в историю.
2. Отмените последнюю операцию, выбрав $v_{k-1}$.
3. Сохраните снимок $s=v_i$ и позднее вернитесь к нему.
4. Из одного снимка создайте $a=push(s,x)$ и $b=pop(s)$ при $|s|>0$. Докажите, что $s$, $a$ и $b$ доступны независимо.

``````{dropdown} Решение
```

**Идея.** История хранит дескрипторы версий; отдельная копия каждого массива не требуется. Для очереди используются те же действия над дескрипторами `persistent.Queue`.

**Корректность.** По индукции $H_i$ указывает на результат первых $i$ операций выбранной истории. Выбор $H_{k-1}$ восстанавливает прежнюю последовательность. Снимок продолжает указывать на неизменяемую структуру независимо от последующих операций; оба продолжения наследуют его содержимое и разделяют доступные узлы.

**Сложность.** Сохранить или выбрать дескриптор — $O(1)$, добавить его в динамический массив истории — амортизированное $O(1)$. Создание продолжения имеет стоимость операции соответствующего контейнера. Удаление дескриптора из истории может освободить последнюю ссылку на $k$ узлов и потребовать $O(k)$ работы; полный откат с освобождением памяти не обязан занимать $O(1)$. Если требуется повторить отменённые действия, сохраните их дескрипторы до удаления ветви из истории.
``````
