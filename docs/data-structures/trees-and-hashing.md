# Деревья поиска, хеш-таблицы и DSU

## Задача

Храните уникальные ключи, выполняя поиск, добавление и удаление. Сравните дерево поиска, хеш-таблицу и DSU.

:::{container} task-facts

**Вход.** Ключи 3, 1, 2 в пустом BST, затем удаление 2.

**Результат.** Обход inorder возвращает (1, 3).

:::

**Предусловия.** Для BST порядок задаётся `<`; ключи хеш-таблицы хешируемы. DSU работает с фиксированным множеством $0,\ldots,n-1$.

### Проверка

Запустите пример: утверждения фиксируют ожидаемое поведение.

```python
from data_structures import binary_search_tree

tree = binary_search_tree.BinarySearchTree[int]()
for value in [3, 1, 2]:
    tree.insert(value)
assert tree.delete(2)
assert tree.inorder() == (1, 3)
```

Структурные контракты: [интерфейсы структур данных](interfaces.md).

Эти структуры отвечают на разные вопросы. Двоичное дерево поиска поддерживает порядок ключей и обход по возрастанию, но без балансировки может стать цепочкой. Хеш-таблица даёт быстрый ожидаемый поиск при равномерном распределении хешей, но не упорядочивает ключи. DSU отвечает на динамический вопрос о связности при последовательных слияниях множеств; она не поддерживает произвольное разделение множества.

## Двоичное дерево поиска

У каждого узла `v` ключи левого поддерева строго меньше `key(v)`, а правого — строго больше. Дубликаты отклоняются. При сравнении предполагается строгий слабый порядок ключей. Эквивалентность определяется как `not a < b and not b < a`; оператор `==` для BST не требуется.

```{literalinclude} ../../src/data_structures/binary_search_tree.py
:language: python
:caption: src/data_structures/binary_search_tree.py
```

Поиск спускается в единственное поддерево, где может находиться ключ: если `x < key(v)`, по инварианту справа ключа `x` быть не может. При вставке мы идём тем же путём до пустой ссылки; добавленный лист удовлетворяет всем ограничениям предков, потому что каждый выбор направления фиксирует ещё одно неравенство. Повторный ключ обнаруживается до изменения дерева.

Удаление имеет три случая. Лист удаляется непосредственно; узел с одним ребёнком заменяется этим ребёнком. Если у удаляемого узла два ребёнка, возьмём минимум правого поддерева `s`. Он не имеет левого ребёнка, а все ключи левого поддерева меньше старого ключа; все остальные ключи правого поддерева больше `s`. Поэтому `s` можно поставить вместо удалённого узла, а его прежнюю позицию занять его правым ребёнком. Порядок BST сохраняется, и удалён ровно один ключ.

Обход preorder посещает корень до детей, inorder — между левым и правым поддеревьями, postorder — после детей. Рекурсивное определение каждого обхода индуктивно по числу узлов: пустое дерево даёт пустую последовательность, а непустое объединяет результаты поддеревьев и ключ корня в указанном месте. Поэтому каждый узел появляется ровно один раз. Из инварианта BST следует, что inorder возвращает строго возрастающую последовательность.

Пусть `n` — число узлов, `h` — высота дерева. Поиск, вставка и удаление занимают `O(h)`, память одной операции — `O(1)` в этих реализациях (не считая глубины стека обхода). Обход занимает `Θ(n)` и `O(h)` памяти для стека. Сбалансированное дерево имеет `h=Θ(log n)`, однако данная структура не балансируется: на отсортированных вставках `h=n`, и операции занимают `Θ(n)`. Она учебно отделяет инвариант поиска от механизмов балансировки.

## Хеш-таблица с цепочками

Таблица хранит список пар `(ключ, значение)` в каждой корзине. Индекс корзины вычисляется как `hash(key) mod capacity`; совпадение индекса не означает равенство ключей, поэтому внутри цепочки ключи сравниваются отдельно. Равные ключи имеют одинаковый хеш — это обязательное условие корректного hash-протокола.

```{literalinclude} ../../src/data_structures/hash_map.py
:language: python
:caption: src/data_structures/hash_map.py
```

Поиск просматривает ровно цепочку корзины ключа; равенство ключа проверяется после выбора по хешу. Вставка обновляет найденную пару или добавляет новую. Удаление вынимает только равный ключ, поэтому коллизия не позволяет затронуть соседнюю запись. При превышении коэффициента заполнения `3/4` таблица удваивает число корзин и заново помещает каждую пару по новому модулю. Инвариант «каждая пара находится в корзине, вычисленной из её текущей ёмкости» сохраняется при переносе; число пар не меняется.

При `n` записях и `m` корзинах коэффициент заполнения `α=n/m`. Если хеши распределяются равномерно, ожидаемая длина цепочки `O(1+α)`. При поддержании `α≤3/4` поиск, вставка и удаление ожидаемо `O(1)`, но худший случай — `Θ(n)`, например при постоянном хеше. Перераспределение занимает `Θ(n)` разово; удвоение ёмкости означает, что конкретная запись переносится лишь при геометрически растущих размерах таблицы, поэтому суммарные затраты переносов за `n` вставок `O(n)`, а амортизированная вставка ожидаемо `O(1)`. Память `Θ(n+m)`. Ожидание зависит от модели хеширования; это не детерминированная гарантия.

## DSU: непересекающиеся множества

DSU хранит разбиение фиксированного множества индексов `0,…,n−1`. В лесу корень каждого дерева — представитель компоненты; `parent[x]=x` для корня. Операция `union(a,b)` находит представителей и связывает корень меньшего дерева с корнем большего. `find` сжимает путь, направляя посещённые вершины сразу к корню.

```{literalinclude} ../../src/data_structures/disjoint_set_union.py
:language: python
:caption: src/data_structures/disjoint_set_union.py
```

Корень остаётся единственным представителем компоненты: сжатие пути меняет только родителей на том же корне, а union связывает два корня и потому объединяет ровно две компоненты. Присоединение меньшего дерева к большему сохраняет корень большего и обновляет его размер суммой. Следовательно, после успешного union число компонент уменьшается на единицу; повторное объединение внутри компоненты ничего не меняет.

Объединение по размеру без сжатия путей ограничивает высоту дерева `O(log n)`: когда глубина узла возрастает, размер его компоненты как минимум удваивается. Сжатие путей вместе с объединением по размеру даёт `O(α(n))` амортизированное время на операцию, где `α` — обратная функция Аккермана, растущая настолько медленно, что для практически достижимых `n` меньше 5. Память `O(n)`. DSU хорошо подходит для добавления рёбер и алгоритма Краскала, но не поддерживает удаление ребра и тем самым разбиение компоненты.
