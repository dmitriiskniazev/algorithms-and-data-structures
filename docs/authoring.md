# Стиль урока

Стиль следует соседнему `design-patterns`: задача → вход и результат → проверка → короткий разбор → код → корректность и сложность. Образец последовательной подачи — [Фибоначчи](algorithms/fibonacci.md); пример задач с раскрываемыми решениями — [стеки и очереди](data-structures/construction.md).

## Содержание

- До первого листинга: наблюдаемая задача, вход, ожидаемый результат, предусловия в LaTeX и короткая исполняемая проверка. Затем идея, код, корректность и сложность.
- Показывать наивное решение и улучшения, когда переход содержателен. Пояснения — короткими пунктами, без пересказа очевидных строк.
- Доказательство: определения, база, переход, результат. Примеры и трассировки нужны для нетривиальных случаев.
- Подключать исполняемый код через literalinclude; полные исходники и тесты доступны для скачивания. Показывать также выделенные процедуры, необходимые для понимания реализации.
- Общие пояснения, контракт и сложность находятся в лекции; не дублировать их docstring в реализации. Комментарий в коде нужен для неочевидного инварианта.
- Предусловия задавать явно; не добавлять проверки входа, assert или лишние ветви ради типизатора.

## Имена

Каждая реализация находится в собственном файле. Одна реализация — самостоятельный модуль, несколько — пакет. Фасад темы экспортирует модули и пакеты. Публичные пространства имён используют полные названия: longest_common_subsequence, knuth_morris_pratt, directed_acyclic_shortest_paths. Сокращения LCS/LIS, BFS/DFS и DSU допустимы в тексте лекции после определения.

- Несколько вариантов: fibonacci.recursive/memoized/tabulated/constant_space, quick_sort.recursive/iterative, order_statistic.recursive/iterative/by_sorting.
- Одна реализация: suffix_array.build, dijkstra.shortest_paths, bubble_sort.sort.
- Структуры: dynamic_array.Stack, fixed_array.Stack, linked_list.Stack, two_queues.Stack, two_stacks.Queue. Способ реализации задаёт модуль, имя класса задаёт структуру.
- Несколько операций с вариантами группируются по операции: binary_search.lower_bound.iterative/recursive и binary_search.upper_bound.iterative/recursive. Файлы реализаций отдельные, __init__.py собирает публичный импорт; [бинарный поиск](algorithms/binary-search.md) — рабочий образец.
- Внутренние шаги приватны; учебные операции со своим контрактом, например build_table и restore_from_table, доступны публично.
- Имена вариантов экспортируются как функции пакета; их файлы реализации приватны (_recursive.py и т. п.), чтобы имя функции не конкурировало с подмодулем.
- __init__.py только собирает публичный импорт. Построение, восстановление и полное решение ДП находятся в отдельных _build_table.py, _restore_from_table.py, _build_parents.py, _restore_from_parents.py и _solve.py/_align.py; общие записи и алиасы — в _types.py, общие алгоритмические помощники — в _common.py.
- Старые имена и совместимые псевдонимы не сохраняются. Полный текущий список — в [карте реализаций](implementations.md).

| Роль | Имена |
|---|---|
| Индексы и счётчики обхода | i, j, k |
| Размеры последовательностей | n, m |
| Границы полуинтервала и середина | left, right, mid |
| Границы группы равных при разбиении | equal_left, equal_right |
| Вершины и координаты | u/v; x/y |
| Расстояния, предшественники, посещённость | dist, parent, seen |
| Последовательность значений | values |
| Вспомогательные массивы | buffer |
| Таблица ДП, предыдущий и текущий слой | dp, prev, curr |
| Собираемый ответ, значение оптимума | ans, val |
| Проверяемый кандидат | candidate |
| Хвосты LIS и их индексы | tails, tail_indices |
| Позиции элементов в индексируемой куче | pos |

Одна роль использует одно имя: i вместо current_index, candidate вместо cand. Предметные поля записей сохраняют смысл: Job.index — исходный индекс интервала, _size — хранимый размер контейнера. Название поля или публичного параметра не обязано повторять локальный математический индекс.

## Аннотации

- Полностью аннотировать параметры и результаты всех функций/методов src/, включая внутренние. Применять синтаксис generics и type-алиасы Python 3.15+.
- Указывать элементы коллекций: list[T], dict[K, V], tuple[int, int], deque[Edit]. Callable задаёт параметры и результат; непараметризованные коллекции и Callable не допускаются.
- Для чтения использовать Sequence, Iterable или Mapping; для изменения последовательности — MutableSequence; возвращаемый конкретный контейнер обозначать его реальным типом.
- Интерфейсы структур описывать структурными Protocol из data_structures.interfaces; mutable и persistent имеют разные контракты. Реализации не обязаны наследоваться от Protocol.
- Для сравнений использовать общий Comparable из algorithms.comparable: единственный оператор — `<`. Обобщённые алгоритмы принимают T: Comparable, без key/reverse/компаратора и перегрузок.
- T обозначает тип значения; K/V — ключ и значение отображения. Содержательные шаги выделять в процедуры; рекурсивная процедура получает границы, буфер и другое состояние явно.
- Nullable-значение читать в локальную переменную, проверять её и использовать ту же переменную. Тип рекурсивного дерева задавать рекурсивным алиасом.
- Не маскировать ошибки через Any, type: ignore или отключение проверок некорректных типов. cast допустим для доказанного инварианта: занятой ячейки контейнера и расстояния уже посещённой вершины.

Протокол сравнения: {download}`Comparable <../src/algorithms/comparable.py>`.

## Динамическое программирование

- Для вариантов одной задачи сохранять обозначения, переходы и порядок вычислений при одинаковом представлении памяти.
- Различать pull/push и объяснять порядок обхода. При сжатии памяти указывать, какие значения уже обновлены; два буфера prev/curr создавать один раз и менять местами.
- Показывать восстановление по значениям и по parent; определять запись parent, условия выбора перехода и полную память, включая историю.
- Шаги всех задач называются build_table, restore_from_table, build_parents, restore_from_parents. Возвращаемые значения и аргументы определяются контрактом конкретной задачи; build_parents возвращает также оптимум и необходимые данные восстановления. Если нужен только оптимум, история не хранится.
- Для плотных состояний использовать индексируемые массивы, для небольшого набора направлений — bytearray с именованными значениями. Сохранять минимальную информацию для восстановления.
- Мемоизацию реализовывать явно: таблица, проверка наличия, сохранение результата.
- Глубокое восстановление выполнять с явным стеком. Индексация Python-строки — по кодовым точкам; нормализация Unicode сама не выполняется.

## Выбор кода и оформление

Полные исходники режима Код собираются из literalinclude и локальных зависимостей; не хранить отдельные копии листингов. Панель тем/шрифтов и настроек следует design-patterns. Новый вариант должен быть доступен через выбор файла; код копируется без номеров и diff-маркеров. Темы оболочки и подсветки генерируются из одного каталога, локальные шрифты поставляются с лицензиями.

## Оформление и проверки

- Одна тема — одна страница с оглавлением. Формулы: $…$ и $$…$$; подробные доказательства — dropdown. Вкладки нужны для содержательно разных вариантов, языковых вкладок нет.
- Общая системная sans-типографика 16px/1.7; код и таблицы используют доступную ширину, обычный текст — до 80ch. Тёмная тема и github-dark, светлая печать. Код — 14px/1.8 с собственной прокруткой; длинные листинги раскрываются нативным details. Заголовок показывает реальный путь, копирование сохраняет текст без подписей. Каталог доступен и на мобильном.
- Лимит Python-строки — 120; короткие сигнатуры помещаются в одну строку. Форматирование выполняет Ruff.
- make check запускает Ruff, Pyright, полный pytest и строгую HTML-сборку. Pyright проверяет весь src/ и положительные примеры; pytest отдельно проверяет, что ошибочные вызовы отклоняются.
- В Pyright выключены только unnecessary isinstance для сохранённых runtime-проверок внешнего входа и private usage для общих помощников вариантов. Проверки неизвестных типов, None, generic-аргументов и совместимости включены.
- В браузере проверять широкий/узкий экран, клавиатуру, раскрытие решений, формулы и печать.


Код в Разборе и Коде использует общие границы, фон и заголовки из `reader/source.css`; не добавлять отдельные стили кнопок для каждого вида листинга. При выключенных «Изменениях» показываются собственные строки каждого файла без добавленных промежутков. Настоящие пустые строки исходника сохраняются; выравнивание включается вместе с diff.
