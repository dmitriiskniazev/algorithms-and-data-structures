# Правила курса и репозитория

## Учебный план

- Темы и их последовательность задаёт пользователь. Не добавлять алгоритмы и структуры данных от себя и не привязывать курс к книге без запроса.
- Точка входа Sphinx — `docs/index.md`, конфигурация — `docs/conf.py`. Для утверждённых тем сначала формулировать задачу и предусловия в LaTeX, затем показывать код и кратко пояснять идею, корректность и сложность. В учебном коде не добавлять проверки предусловий без содержательной необходимости.
- Рабочий цикл темы: согласовать контракт → создать узкий OpenSpec change → реализовать Python-решение и тесты → обновить страницу курса и ссылки на исходники.
- Не начинать реализацию следующей темы, пока пользователь не предоставил план или конкретное задание.

## Исходники и языки

- Курс использует только Python 3.15+; новые языки добавлять только по запросу.
- Исходники и тесты хранить в корневых `src/` и `tests/`. Алгоритмы размещать под `src/algorithms/<topic>/`, структуры данных — под `src/data_structures/`. Каждая реализация находится в собственном файле. Одна реализация — модуль, несколько реализаций сущности — пакет; не создавать слой `<name>/<name>.py` ради единственного исходника. Тесты повторяют то же дерево под `tests/`.
- Не создавать пустые каталоги или файлы. Структура появляется вместе с содержательным исходником или тестом.
- Общие идеи и свойства алгоритма описывать в лекции, не дублировать документацию в коде.
- Курс оформлять по стилю соседнего `design-patterns`: наблюдаемая задача, вход/результат, короткая проверка, затем идея, исходник, корректность и сложность. Нейтральные примеры; единая sans-типографика, свободная ширина для кода/таблиц, длинные подробности по запросу.
- `__init__.py` содержит импорты и `__all__`, а не реализации. Каждая самостоятельная учебная операция и композиция полного решения находится в собственном файле; общие типы и переиспользуемые помощники не дублируются.
- В вариантах одного алгоритма сохранять одинаковые обозначения, порядок вычислений и переходы, где это содержательно. Использовать общепринятые обозначения (`dp`, `parent`, `prev`, `curr`, `i`, `j`, `k`, `n`, `m`, `tails`); смысл задавать в лекции.
- Python: использовать uv, Python 3.15+, generic-параметры и общий протокол сравнения.
- Фасады экспортируют модули/пакеты. Несколько вариантов: `fibonacci.recursive/memoized/tabulated/constant_space`, `quick_sort.recursive/iterative`; один вариант: `suffix_array.build`, `bubble_sort.sort`. Публичные названия полные, без LCS/KMP/DAG; варианты функций короткие. Файлы вариантов приватны, чтобы имена функций не конкурировали с подмодулями.
- Семейство с несколькими операциями и вариантами группировать по операции: `binary_search.lower_bound.iterative/recursive`, `binary_search.upper_bound.iterative/recursive`. Каждый вариант — отдельный файл; `__init__.py` экспортирует функции. Образец — `src/algorithms/searching/binary_search/`.
- Классы: `dynamic_array.Stack`, `fixed_array.Stack`, `linked_list.Stack`, `two_queues.Stack`, `two_stacks.Queue`. Вариант задаёт модуль, класс называет структуру. Прежние имена и совместимые псевдонимы удаляются.
- Шаги ДП: `build_table`, `restore_from_table`, `build_parents`, `restore_from_parents`; полные сигнатуры и состав результатов задаются конкретной задачей.
- Локальные имена краткие и отражают роль: `i/j/k`, `n/m`, `left/right/mid`, `u/v`, `dist`, `parent`, `prev/curr`, `dp`, `values`, `buffer`, `candidate`. Предметные имена сохраняют смысл; не заменять их механическими сокращениями.
- Все функции и методы `src/` аннотировать полностью. У коллекций и `Callable` указывать параметры типов; сохранять тип значения через generics, использовать `Sequence`/`Iterable`/`Mapping` для чтения. Для порядка использовать единый `Comparable` из `algorithms.comparable` и прямой `<`, без key/reverse/компаратора и перегрузок. Минимальные/максимальные очереди — явные модули minimum/maximum. Содержательные процедуры выделять; состояние рекурсии передавать явно.
- `stack.extrema` и `queue.extrema` симметричны: только `minimum`/`maximum`, запрос `extreme()`. Очередь использует два стека соответствующего варианта.
- Интерфейсы существующих структур задавать структурными Protocol в `data_structures.interfaces`, каждый в отдельном файле. Различать изменяемые и персистентные результаты; не требовать наследования или runtime-проверок.
- Не заменять точную модель через `Any`, `type: ignore` или отключение диагностики некорректных типов. `cast` допустим только на явной границе доказанного инварианта; не добавлять runtime-проверки ради анализатора.
- Проверки: `uv run --locked ruff check src tests/typing`, `uv run --locked ruff format --check src tests`, `uv run --locked pyright`, `uv run --locked python -m pytest` и `make docs`; вместе — `make check`.
- Общие настройки Make и uv находятся в корне.

## Spec-Driven Development

- Перед работой читать относящиеся к задаче основные спеки и активные OpenSpec changes.
- Для отдельной возможности создавать узкий change с проверяемой spec delta и tasks. `design.md` нужен только для решений, которые следует сохранить.
- Строго валидировать change до реализации, выполнять и отмечать его задачи, запускать указанные проверки. Архивировать после завершения реализации и проверок.

## CodeGraph

Если в корне есть `.codegraph/`, перед поиском или чтением исходников сначала изучить код через `codegraph explore`. Индекс генерируется локально и не коммитится.

## Git

- Перед серией коммитов показать короткий план содержимого каждого коммита.
- Делать небольшие тематические коммиты. Не отправлять их на удалённый сервер без прямого запроса.

## Общие ресурсы интерфейса

`course-engine` находится только в группе `docs`; его полный Git SHA в `pyproject.toml` и `uv.lock` фиксирует опубликованную версию. Темы, настройки, панель, шрифты с лицензиями и общий просмотр кода поставляет пакет. Не добавляйте поддерживаемые копии в `docs/_static`. Адаптер `docs/_ext/course.py` готовит ресурсы в генерируемом doctreedir до HTML-рендера; Sphinx копирует их в результат `_static`; учебные страницы и навигация остаются у Sphinx. Общие изменения проверяйте на обоих курсах. CI не должен зависеть от `../course-engine`.
