# sorting-algorithms Specification

## Purpose

Определяет поведение учебных реализаций сортировок и требования к их объяснению в курсе.

## Requirements

### Requirement: Базовые сортировки упорядочивают изменяемую последовательность

Реализации Bubble Sort, Insertion Sort и Selection Sort SHALL переставлять элементы на месте и по умолчанию упорядочивать их по возрастанию. Python API SHALL принимать изменяемую последовательность и keyword-only параметры `key=None` и `reverse=False`; функция SHALL возвращать `None`, а переданный `key` SHALL вычисляться один раз на элемент. C++26 API SHALL принимать `comp` и `proj`, предоставлять перегрузки для итераторов с sentinel и для range, а range-перегрузка SHALL делегировать алгоритму для итераторов. Реализации SHALL поддерживать пользовательский порядок без фиксации на порядке по возрастанию.

#### Scenario: Сортировка по умолчанию
- **WHEN** алгоритм вызывается без настройки порядка
- **THEN** он сортирует элементы по возрастанию на месте

#### Scenario: Python получает ключ и обратный порядок
- **WHEN** Python-алгоритм вызван с `key` и/или `reverse=True`
- **THEN** он вычисляет ключ ровно один раз для каждого исходного элемента и сортирует согласно этим ключам

#### Scenario: C++ получает компаратор и проекцию
- **WHEN** C++26-алгоритм вызван с `comp` и `proj`
- **THEN** он сравнивает проецированные значения в порядке, определённом `comp`

#### Scenario: C++ принимает несовпадающий sentinel
- **WHEN** итераторная перегрузка получает sentinel, тип которого отличается от типа итератора
- **THEN** алгоритм корректно обрабатывает полуоткрытый диапазон без требования `common_range`

### Requirement: Реализации показывают отличительные шаги алгоритмов

Bubble Sort SHALL сравнивать и при необходимости менять местами соседние элементы, завершаться досрочно при проходе без обменов и сохранять устойчивость. Insertion Sort SHALL поддерживать отсортированный префикс, сдвигать только элементы, которые должны идти после вставляемого, и сохранять устойчивость. Selection Sort SHALL выбирать очередной минимальный по заданному порядку элемент оставшейся части и помещать его на следующую позицию; алгоритм SHALL NOT обещать устойчивость. Все три реализации SHALL использовать O(1) дополнительной памяти, не считая Python-кэша ключей.

#### Scenario: Вход уже упорядочен
- **WHEN** Bubble Sort получает последовательность, упорядоченную согласно переданному порядку
- **THEN** один проход без обменов завершает алгоритм

#### Scenario: Равные ключи во вставочной сортировке
- **WHEN** Insertion Sort обрабатывает элементы с равными ключами
- **THEN** относительный порядок таких элементов сохраняется

### Requirement: Урок объясняет первые сортировки через код

Страница Sphinx по сортировкам SHALL содержать исполняемо выглядящие реализации Python и C++26 для трёх алгоритмов, краткую идею каждого, объяснение корректности, устойчивость и временную/пространственную сложность. Страница SHALL ссылаться на файлы исходников и тестов. Документация SHALL NOT добавлять другие сортировки, не перечисленные в этой возможности.

#### Scenario: Читатель изучает сортировку
- **WHEN** читатель открывает страницу урока
- **THEN** он видит код алгоритма и может перейти к исходнику и тестам соответствующего языка
