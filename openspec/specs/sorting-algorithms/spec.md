# sorting-algorithms Specification

## Purpose

Определяет поведение учебных реализаций сортировок и требования к их объяснению в курсе.

## Requirements

### Requirement: Реализации показывают отличительные шаги алгоритмов

Bubble Sort SHALL сравнивать и при необходимости менять местами соседние элементы, завершаться досрочно при проходе без обменов и сохранять устойчивость. Insertion Sort SHALL поддерживать отсортированный префикс, сдвигать только элементы, которые должны идти после вставляемого, и сохранять устойчивость. Selection Sort SHALL выбирать очередной минимальный по < элемент оставшейся части и помещать его на следующую позицию; алгоритм SHALL NOT обещать устойчивость. Все три реализации SHALL использовать O(1) дополнительной памяти.

#### Scenario: Вход уже упорядочен
- **WHEN** Bubble Sort получает последовательность, упорядоченную по <
- **THEN** один проход без обменов завершает алгоритм

#### Scenario: Равные ключи во вставочной сортировке
- **WHEN** Insertion Sort обрабатывает эквивалентные по < элементы
- **THEN** относительный порядок таких элементов сохраняется

### Requirement: Урок объясняет первые сортировки через код

Страница Sphinx по сортировкам SHALL содержать исполняемо выглядящие реализации Python для трёх алгоритмов, краткую идею каждого, объяснение корректности, устойчивость и временную/пространственную сложность. Страница SHALL ссылаться на файлы исходников и тестов. Документация SHALL NOT добавлять другие сортировки, не перечисленные в этой возможности.

#### Scenario: Читатель изучает сортировку
- **WHEN** читатель открывает страницу урока
- **THEN** он видит код алгоритма и может перейти к исходнику и тестам соответствующего языка

### Requirement: Сравнительные сортировки используют прямое сравнение значений

Bubble Sort, Insertion Sort и Selection Sort SHALL сортировать изменяемую последовательность на месте по возрастанию относительно < и возвращать None. Сами элементы SHALL задавать строгий слабый порядок через __lt__. Параметры key/reverse и передаваемый компаратор SHALL отсутствовать; кэш ключей SHALL NOT создаваться.

#### Scenario: Сравниваемые объекты
- **WHEN** элементы поддерживают только __lt__, а эквивалентные значения различаются содержимым
- **THEN** все значения упорядочены по <; устойчивые реализации сохраняют порядок эквивалентных элементов

#### Scenario: Пустой и упорядоченный вход
- **WHEN** сортировка получает пустую, одноэлементную или упорядоченную последовательность
- **THEN** результат корректен без выделения кэша ключей
