# Build and Test Specification

## Purpose

Фиксирует общую настройку языковой среды и команды сборки и проверок для учебных примеров на C++26 и Python.

## Requirements

### Requirement: Примеры C++ используют C++26

Корневой проект CMake SHALL требовать стандарт C++26 и отключать расширения компилятора для целей C++. Реализации алгоритмов SHALL экспортироваться как named modules. Сборка модулей SHALL выполняться через поддерживаемую версию CMake и поддерживаемый CMake-генератор. Корневые команды проекта SHALL использовать Ninja 1.11 или новее.

#### Scenario: Настраивается цель C++
- **WHEN** CMake конфигурирует исходник C++
- **THEN** цель использует требуемый стандарт C++26 без расширений компилятора

#### Scenario: Корневая команда собирает модули
- **WHEN** участник запускает `make test-cpp` при наличии C++-тестов
- **THEN** корневая команда конфигурирует CMake с Ninja, собирает цели и запускает CTest

#### Scenario: Тест импортирует named module
- **WHEN** C++-тест импортирует фасад или модуль алгоритма
- **THEN** CMake сканирует зависимости модулей и собирает модуль-поставщик перед импортирующей целью

#### Scenario: C++ файл импортирует стандартный заголовок
- **WHEN** модуль или тест использует стандартные объявления C++
- **THEN** файл объявляет `import std;`, а CMake предоставляет скомпилированный модуль `std` без ручной сборки BMI

#### Scenario: Логические выражения используют словесные операторы
- **WHEN** C++-код выражает логическое отрицание, конъюнкцию или дизъюнкцию
- **THEN** он использует `not`, `and` или `or` соответственно

#### Scenario: Сортировки используют общий диапазон
- **WHEN** вызывается range-перегрузка сортировки C++
- **THEN** Bubble Sort принимает forward range, а остальные сортировки требуют категории range, необходимой их алгоритму; перегрузки корректно обрабатывают sentinel конца и не требуют `common_range` без отдельной необходимости

### Requirement: Python-среда управляется uv

Общий `pyproject.toml` и lock-файл uv SHALL находиться в корне; проект SHALL требовать Python 3.15 или новее; зависимости разработки SHALL устанавливаться в корневое виртуальное окружение.

#### Scenario: Настраивается Python-среда
- **WHEN** участник запускает `make setup` под Python 3.15 или новее
- **THEN** uv синхронизирует Python-зависимости проекта и pytest обнаруживает тесты внутри `impl/python/tests/`

#### Scenario: Более старая версия Python отклоняется
- **WHEN** участник пытается использовать для проекта версию Python ниже 3.15
- **THEN** конфигурация проекта сообщает, что версия не удовлетворяет требованию

### Requirement: Общие команды запускаются из корня

Корневой Makefile SHALL предоставлять команды настройки, C++ и Python проверок и форматирования C++ и SHALL запускать тесты из деревьев `impl/cpp/` и `impl/python/`, если такие тесты существуют.

#### Scenario: Запущен полный набор проверок
- **WHEN** участник запускает `make test`
- **THEN** запускаются доступные C++ и Python проверки из `impl/cpp/tests/` и `impl/python/tests/`

#### Scenario: Реализаций и тестов пока нет
- **WHEN** участник запускает `make test` в чистом каркасе курса
- **THEN** команда завершается успешно и сообщает, что тестов пока нет

#### Scenario: Проверено форматирование C++
- **WHEN** участник запускает `make check-format-cpp`
- **THEN** clang-format проверяет все исходники C++ в `impl/cpp/` или сообщает, что исходников пока нет

### Requirement: Редактор получает команды сборки модулей

Конфигурация CMake SHALL по умолчанию экспортировать `compile_commands.json`. Локальная настройка VS Code SHALL распознавать `.cppm` как C++ и использовать установленный clangd, совместимый с компилятором сборки, с экспериментальной поддержкой модулей и базой команд из `build/cpp`. Документация SHALL описывать настройку и экспериментальный статус поддержки.

#### Scenario: Настраивается C++ сборка
- **WHEN** участник запускает `make setup-cpp`
- **THEN** в `build/cpp` создаётся база команд для исходников модулей и тестов

#### Scenario: Редактор анализирует импортирующий файл
- **WHEN** clangd анализирует C++ файл после сборки проекта
- **THEN** он получает стандарт C++26 и зависимости модулей из реальной команды сборки

#### Scenario: VS Code конфигурирует проект
- **WHEN** участник запускает конфигурацию через CMake Tools
- **THEN** локальная настройка явно выбирает Ninja и совместимый Clang, используя тот же каталог `build/cpp`, что и clangd
