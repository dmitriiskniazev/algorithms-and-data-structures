# Repository Workflow Specification

## Purpose

Определяет, как агент фиксирует запрошенную работу, проверяет её требования и сохраняет завершённые изменения в OpenSpec.

## Requirements

### Requirement: Изменения реализуются через ограниченный OpenSpec change

Запрошенная реализация или структурное изменение SHALL иметь proposal, проверяемые требования и задачи в одном узком OpenSpec change. Артефакт `design.md` SHALL создаваться только когда нужно сохранить техническое решение. Независимые возможности SHALL описываться отдельными changes.

#### Scenario: Однозначно запрошена реализация
- **WHEN** пользователь просит реализацию с понятным поведением
- **THEN** агент фиксирует её границы и проверяемые требования, затем выполняет включённые задачи в рамках этой работы

#### Scenario: Неясен контракт или объём
- **WHEN** неоднозначность может изменить поведение или границы реализации
- **THEN** агент запрашивает решение пользователя до выполнения зависимой работы

#### Scenario: Change завершён
- **WHEN** задачи выполнены и обязательные проверки прошли
- **THEN** change проходит строгую валидацию и только после этого архивируется
